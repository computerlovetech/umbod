# Shared backend integration

This package is the desktop-owned outer adapter layer. The dependency graph is runtime composition → these adapters → desktop contracts and ports. Migration, naming repair and aggregate recording depend on desktop ports, not this package, HTTP or shared backend types. The package initializer intentionally exports nothing; composition imports each adapter explicitly.

## Module index

- `administration.py`: `BackendAdministration` owns the authenticated httpx ASGI client and exact `/api/admin` connector, discovery, tool activation, publication and group-grant translations. Repair-only prefix PATCH translation is owned by the compatibility adapter, which borrows this client without owning closure. Inventory and creation become immutable desktop connector definitions; tool responses become tuples of names. Its HTTP helper is private. Status failures become desktop administration rejections; transport failures become desktop administration errors without response or credential text. Runtime owns closure, not migration.
- `authentication.py`: owner/admin and current agent token verifiers implement the supported hosting contracts. An injected credential predicate defaults to rejection; historical hash matching belongs exclusively to `backward_compatibility/authentication.py`. Desktop vault and loopback authentication remain in `security.py`; the credential port and desktop group identity belong to desktop ports/contracts.
- `configuration.py`: maps a required, already-loaded immutable `DesktopSettings` snapshot to hosting `AppConfig`. It never reloads a profile or operator environment. Existing encryption derivation labels and storage settings remain unchanged.
- `naming.py`: implements the desktop naming policy with the backend's existing readable-prefix and public-name collision functions; it does not normalize names independently.
- `oauth.py`: permanent Keychain OAuth storage and host connection/callback composition. Historical credential conversion lives only in [`../backward_compatibility/`](../backward_compatibility/README.md), with its own narrow authorization-document import. Resource comparisons, absolute expiry, refresh data, serialization and stale-write rejection retain backend OAuth persistence semantics. Existing Keychain references and callback routes are unchanged.
- `transports.py`: stdio/Streamable HTTP proxy infrastructure, single-task proxy lifespans, OAuth runtime authentication and response-status observation. It implements upstream preparation, proxy configuration and binding through desktop DTOs while keeping existing persistence dictionaries. Runtime serializes preparation DTOs to the existing `/desktop/upstreams` JSON shape.
- `models.py`: shared EndpointUrl-based validation of native transport requests. `loopback_origin` remains desktop-owned in `models.py` outside this package.
- `usage.py`: filters nonconnector invocations and authorization/validation failures, then maps hosting invocation events to desktop completion DTOs consumed by the injected recorder.

## Supported and residual coupling

Hosting root imports are the supported backend composition boundary. Administration deliberately uses the shared HTTP JSON API rather than backend repositories or REST internals. Residual deep imports are restricted by consumer file, module and symbol: configuration uses `derive_secret`; naming uses `default_tool_name_prefix` and `mangle_public_tool_name`; transport validation uses `EndpointUrl`; OAuth storage uses `AuthorizationDocument`, `ConnectorOAuthStorage`, `SignInRequired` and `OAuthConnection`; transports use `RuntimeOAuth` and `response_authentication_status`. OAuthService comes from hosting. The compatibility OAuth adapter separately imports only `AuthorizationDocument` for historical conversion. No adapter imports deep REST/MCP modules or hosting implementation submodules.

Runtime retains REST construction, adapter/migration setup, MCP construction, then REST lifespan, independent naming repair, MCP lifespan and upstream restoration. Shutdown closes administration, OAuth and upstreams in that order before MCP and REST lifespans exit. This refactor does not add application-state service lookup, broaden shared lifetimes or promise additional construction rollback.

Desktop owns the protocols in `ports.py`, including the small shared metadata `data`/`save` protocol. `DesktopState` structurally implements that protocol; use cases do not import the filesystem adapter. Migration's legacy source reads and atomic backup remain explicit desktop-local filesystem coupling through `persistence.py`, not a claim that all desktop I/O is inverted.

Changes to supported hosting exports, HTTP JSON, desktop credentials, preparation DTO serialization, OAuth persistence or startup/shutdown semantics require compatibility review and corresponding contract tests. Private adapter paths are not compatibility shims for deleted desktop modules. Desktop and API hosting AST tests enforce direct and transitive dependency direction and exercise forbidden synthetic imports. In-memory administration, naming, metadata, authorization and upstream doubles prove the desktop ports without constructing the backend; real backend tests retain runtime/OAuth/settings coverage.
