# macOS desktop host

The SwiftUI app keeps its native screens. `AdministrationClient.swift` maps the shared `/api/admin` connector, discovery, publication, activation and group-permission APIs to the existing native presentation model. The host composes those REST and MCP applications; it does not implement a second connector registry or permission engine.

## Entry points and ownership

- `main.py`: packaged `serve` and `bridge` commands, loopback socket, stable port, process lock, readiness pipe, owner shutdown and dev/release isolation. Its `credential` command lets Swift reattach through a private pipe using the same installed backend identity; Swift does not access Keychain independently. Legacy positional bridge identities remain accepted. `build.sh` bundles a relocatable interpreter and locked dependencies, then signs a fresh bundle.
- `runtime.py`, `backend_integration/configuration.py`: shared application composition and authenticated `/desktop` routes. SQL event polling synchronizes API writes with MCP. Native single-tool and bulk enablement publish the connector before applying activation and batched permissions; rename-only saves preserve the live transport. Native removal revokes the selected connector’s desktop-owner grants, including stale tool grants, before deleting its registry entry and transport. Dedicated metrics listeners are disabled for desktop. MCP defaults to gateway exposure (`search_tools` and `execute_tool`); saved backend settings select gateway, flat or codemode before constructing the application. Settings never hot-swap registered tools.
- `contracts.py`, `ports.py`: immutable desktop DTOs and semantic administration, naming, invocation recording, metadata and upstream preparation protocols. Use cases consume these ports; `DesktopState` satisfies the shared metadata protocol without a persistence rewrite. `CredentialVault` and `DESKTOP_GROUP` remain available through their established public security imports.
- [`backend_integration/`](umbod_desktop/backend_integration/README.md): concrete HTTP administration, hosting authentication/configuration, shared naming, Keychain OAuth, transport and usage mapping adapters. Permanent backend adapters live here; the compatibility OAuth adapter has a narrow historical conversion import, and runtime additionally uses supported hosting root composition exports.
- `security.py`: separate random admin, agent, upstream and encryption credentials in macOS Keychain. No development auth or plaintext fallback. Existing agent token hashes are retained for migration; they never grant REST owner access. Agent identities receive `desktop-owner`, so opting into administrator MCP tools grants all of these clients MCP administration access.
- `backend_integration/transports.py`, `backend_integration/models.py`: validated stdio and Streamable HTTP transports exposed through private authenticated loopback proxies to the shared downstream connector API. A proxy owns its lifespan in one task. Offline drafts remain editable and cannot retain an obsolete live transport after an invalid edit. Upstream HTTP challenges and runtime OAuth reauthentication persist a sign-in-required status; successful requests clear it. The private loopback bearer is consumed before proxying, so only connector-owned credentials reach upstream servers.
- `backend_integration/oauth.py`: macOS Keychain storage and the `DesktopOAuthHost` adapter for shared OAuth connection storage, stable loopback callback addresses, and local transport reconnection. `callback_transport` forwards callback parameters to shared protocol validation. Discovery, public-client registration, scopes, status transitions, safe errors, diagnostics, cancellation, token exchange/refresh, and authorization-versus-discovery outcomes live in `umbod.core.connectors.downstream_mcp.oauth`. Native clients use the shared `/api/admin/connectors/mcp/oauth` API; private `oauth_*` host actions are no longer supported. Existing callback paths and Keychain records remain compatible.
- [`backward_compatibility/`](umbod_desktop/backward_compatibility/README.md): exclusively historical settings import, generated tool-prefix repair, authenticated old-host retirement, legacy OAuth conversion, saved-port fallback and migrated agent hash matching. Migration-only contracts and adapters live inside this removable package. Original settings and Keychain entries are preserved; no PID from disk is signalled. Its index describes lifecycle entrypoints and the deletion checklist. New connections use permanent backend naming rather than compatibility repair.
- `endpoint.py`: validates the current `python-endpoint.json` port independently of historical formats; `main.py` explicitly supplies the compatibility fallback.
- `settings.py`: strict exposure-mode and boolean administrator settings, defaulting to gateway/off for existing profiles. `GET /desktop/settings` returns `pending`, immutable process `effective`, and `restart_required`; `PUT /desktop/settings` validates and atomically saves pending values without changing the running app. Both require the private owner/admin bearer; the agent token cannot access this API even when administrator MCP is enabled. Swift verifies health and reads back effective settings after restarting. Unknown modes, malformed booleans and unexpected fields are rejected. Invalid persisted settings fail closed without rewriting or resetting the profile; repair only the `settings` object (or restore its valid backup), leaving connectors, credentials, migration journals and grants intact. Operator `.env` settings remain ignored.
- `persistence.py`, `storage.py`, `usage.py`: owner-only atomic file helpers, host metadata and typed aggregate completion recording, without arguments or results. `backend_integration/usage.py` filters and maps hosting events before recording. Shared connectors and encrypted configuration live in `backend.sqlite3`.
- `client_setup.py`: consented configuration previews, conflict detection and byte-preserving backup restoration.
- `testing.py`: explicitly selected fixture credentials, restricted to owned `umbod-test-*` directories under the system temporary directory. This is never a fallback for unavailable Keychain access; normal profiles always use Keychain.
- `tests/`: real HTTP/stdio MCP calls, default-deny and live revocation, resumable import, authentication isolation, OAuth refresh/callback races and safe client-file editing. Native tests additionally exercise the packaged interpreter, an explicit disposable fixture vault and persistent-process reattachment. Routine tests never open the user’s Keychain. Automated native UI and window-lifecycle tests are currently removed.

## Shared backend extension points

`runtime.py` is the outer composition root. Desktop use cases depend on `ports.py` and `contracts.py`; `backend_integration` implements those desktop-owned ports. Supported backend assembly, verifiers, configuration and invocation events come from [`umbod.hosting`](../../umbod/api/src/umbod/hosting/README.md). Integration adapters retain exact naming, secret derivation, EndpointUrl and OAuth storage/connection/provider imports, detailed in their index; the compatibility OAuth adapter separately owns historical authorization conversion. The shared administration HTTP JSON contract remains authoritative. This is dependency inversion for desktop use cases, not a replacement backend or a claim that all desktop-local file I/O is abstracted.

Runtime loads DesktopState before mapping its immutable settings snapshot. Administration owns the authenticated ASGI client, and runtime closes it in the former migration-client callback position. Naming repair is composed independently of migration. Existing startup/shutdown order, credentials, journal dictionaries and public JSON remain unchanged. Changes to these interfaces require explicit compatibility review and updated contract tests. `tests/test_architecture.py` and API hosting boundary tests walk nested imports, resolve relative imports, check exact residual symbols by adapter file and test their scanners against violating snippets; desktop tests additionally verify transitive use-case independence.

Shared backend host extension points include OAuth storage/callback composition, an explicitly supplied REST identity verifier, optional REST/MCP metrics listeners (enabled by default), SQL-backed group permission reloads, and an injectable MCP invocation sink. The host injects the shared `OAuthService` through the `oauth_service` hook on `create_rest_app` and closes it with the bundled process lifecycle. Enterprise verifier selection and domain behavior retain their defaults. Desktop authentication is fixed to one local owner and one permission group.

The desktop host provides authenticated stdio/HTTP transport adapters instead of adding desktop subprocess, Keychain or browser lifecycle behavior to the shared core. The REST API remains the authority for connector discovery, tool activation, publication and permissions.

## Recovery and lifecycle

A persistent launch installs an immutable runtime under the profile's `runtimes/<build-id>/Contents`, with stable bridge links under `bin/`. Closing the app leaves it running; reopening authenticates and checks its profile/PID. A new app build reports a restart requirement while the existing process continues. A gateway watches the identity of its profile directory and lock and exits if either is moved or replaced, so an orphan cannot consume the replacement profile’s events. Shutdown removes only its own runtime record. A saved-port conflict or missing encryption credential fails closed rather than generating new identities or silently changing the endpoint.

Migration writes `config.before-python.json` and a journal in `desktop-v2.json`; repeated imports recover connectors by deterministic public path. Failed imports preserve their original source and display a repair message. Do not delete the SQLite database or Keychain root secret to retry. Existing bridge command paths and HTTP credentials are retained, but clients must rediscover the shared backend's tool names. The current native workspace uses connector setup and Settings → MCP.

Run `uv run --locked pytest` and `uv run --locked ruff check .` here. From `desktop/`, `bash scripts/verify.sh` builds and verifies the actual macOS bundle. Shared application changes also require the API/MCP tests and `bash umbod/tests/kind-runtime/run.sh` from the repository root. Ad-hoc local verification is not clean-machine Gatekeeper/notarization certification.

CI runs `scripts/keychain-smoke.py` only on disposable GitHub-hosted runners, using a newly created temporary Keychain that is removed afterward. It verifies real credential reads and restart continuity. This is not a test of approval prompts for a particular user’s legacy Keychain items. A locked Keychain or the first access to legacy items may still need approval; production signing must provide a stable application identity across interpreter upgrades. Local builds remain ad-hoc signed. Routine verification does not ask for a password or change Keychain access controls.
