# Hosting

Backend-owned composition API shared by the macOS host and the separate Kubernetes REST and MCP services. This package changes composition ownership, not routes, authentication defaults, transports, or deployment topology.

## Supported API

Import host-facing functions and contracts from `umbod.hosting`. The synchronous `create_rest_app` returns FastAPI; asynchronous `create_mcp_app` returns Starlette. Both require an explicit `AppConfig`. Importing this package does not load environment configuration or construct applications.

Supported contract reexports are `AppConfig`, `ConnectorRegistration`, `JwtVerifier`, `JwtClaims`, `JwtVerificationError`, `OAuthService`, `MCPAuthProvider`, `InMemoryGroupConnectorToolPermissions`, `McpToolInvocationLogSink`, `McpToolInvocationLogEvent`, `AccessToken`, and `TokenVerifier`. These retain the underlying types' identity. Annotations describe contracts; they do not check protocol conformance at runtime.

REST accepts connector registrations, admin verifier and OAuth service hooks. MCP accepts auth provider, group permission runtime state and completed-invocation sink hooks. Every hook is a required keyword-only argument: callers explicitly supply None for configured/default selection or supply an override. Optional types deliberately model that choice at the host composition boundary. None does not disable configured authentication or logging. An empty REST registration sequence remains an explicit override.

`applications.py` assembles existing backend applications; `contracts.py` owns supported reexports. Internal MCP configuration and runtime contexts are not host contracts. Hosts should not import hosting implementation submodules. Changes to the documented signatures, reexports, override semantics or resource ownership require explicit compatibility review and migration guidance; internal backend modules may evolve independently.

## Ownership and lifecycle

The host owns loopback sockets, credentials and identity policy, native transport adapters, migration, local metadata and aggregate usage, and supplied OAuthService shutdown. Backend app lifespans own persistence, metrics listeners, MCP workers and existing synchronization tasks. Hosts must enter both returned ASGI lifespans. Desktop retains REST construction, migration setup, MCP construction, then REST lifespan, tool-name repair, MCP lifespan and upstream restore.

MCP composition closes acquired persistence on configuration acquisition or later construction failure, including cancellation. Successful composition leaves shutdown to the existing lifespan. This is not a general rollback guarantee for all constructed collaborators. REST delegates unchanged to its legacy factory: persistence is created before startup validation and later assembly, and those construction failures are not covered by its lifespan shutdown. This API does not claim REST construction rollback.

## Services and remaining coupling

`rest_service.py` is the zero-argument Uvicorn factory; it loads .env, configures logging and constructs REST. `mcp_service.py` exports a lightweight Starlette shell that is safe to import inside an active event loop. Its ASGI lifespan loads .env, configures logging, awaits MCP composition in that loop and enters the returned application's lifespan. It mounts the application for HTTP forwarding only while that lifespan is active and removes its mount on exit. Import does not load settings or construct the backend MCP application. Construction and startup failures propagate through ASGI startup. CLI services remain separate processes. The legacy REST factory retains its existing invocation forms; legacy MCP main exports the same shell object, and legacy MCP production factories delegate to hosting composition. Kubernetes chart wiring is unchanged.

Explicit settings avoid operator .env loading, but native connector deployment declarations still come from `UMBOD_CONNECTOR_DEPLOYMENT_CONFIGURATION_PATH`. Shared settings still expose HTTP endpoints, persistence choices and OAuth storage details. Backend synchronization can still use system HTTP endpoints or SQL events. Desktop confines shared backend dependencies to `umbod_desktop/backend_integration` and hosting-root runtime composition. Its migration, naming repair and usage recorder depend on desktop-owned DTOs and semantic protocols, including a shared metadata protocol, not HTTP clients or backend models. The administration adapter owns authenticated `/api/admin` JSON translation and runtime-owned client closure. Exact residual imports remain limited to the naming functions, secret derivation, EndpointUrl, OAuth authorization storage/connection and runtime provider symbols documented in the desktop integration index. Both desktop and hosting tests independently scan nested/relative imports and reject unsupported file/module/symbol combinations; synthetic violations protect the scanners. Desktop tests also enforce transitive use-case independence. Legacy source/backup filesystem I/O remains an explicitly incremental desktop-local boundary. This facade does not remove those residual OAuth/HTTP/configuration couplings or introduce a separate desktop backend.
